## 검증한 흐름

- 실제 한국어 OCR 엔진으로 테스트용 영수증 이미지의 날짜·상호·금액·승인번호 자동 채움, 원본 대조 후 등록.
- 빈 사진의 실제 인식 실패, 다시 촬영해도 실패 횟수 유지, 3회 후 수기 전환·관리팀 제출 안내.
- 엔진 다운로드 오류, 느린 다운로드 중 취소, 취소 시 실패 횟수 증가 없음.
- 이미지·전체 OCR 텍스트가 서버/Firestore로 전송되지 않으며 엔진·언어 파일은 같은 사이트에서 GET만 하는지 검사.
- 정상 직접 입력, 소수 금액을 다른 숫자로 바꾸지 않고 거부, 실제 승인번호 없음, 필수정보 공란과 참석인원 0·100·문자·소수·특수문자 차단.
- 사용자 확인 후 등록, 등록 중 요청 잠금, 저장 실패 시 입력 유지, 커밋 응답 유실 후 재시도 한 건만 저장, 동일 승인정보 중복 차단.
- 직원 이름/사번·등록번호로 처리상태 조회.
- 관리자 최초 화면 잠금 설정, 잘못된 비밀번호 거부, 직원·관리자 화면 구분.
- 기간·사용자 검색, 상세 내역, 수정·중복 재검사·버전 충돌, 상태 확인/취소/완료/되돌리기.
- 삭제 확인창과 체크박스, 해당 등록내역·중복키만 삭제.
- 현재 검색 결과 CSV 다운로드, UTF-8 BOM·한글·따옴표·스프레드시트 수식 방어.
- PC·갤럭시·아이폰 크기에서 가로 넘침 없이 전체 흐름 동작.
- 이미지가 Firestore 요청에 포함되지 않고 저장값이 `imageStored:false`인지 검사.

브라우저 자동 테스트는 테스트 전용 Firestore REST 대역으로 정상/오류/응답 유실을 재현합니다. 운영 앱에는 대역이 포함되지 않습니다. 실제 Firestore 테스트는 `_receiptIntegrationTests`, `_receiptIntegrationDuplicateTests`에 임시 문서를 생성하고 **이번 실행에서 생성한 문서와 중복키만** 정리했습니다. 기존 `receipts` 문서와 실제 관리자 잠금 설정은 변경하지 않았습니다.

초기 진단에서 익명 `beginTransaction`이 권한 오류로 거부되는 것을 확인해 `exists`/`updateTime` 조건과 원자적 `commit`으로 수정했습니다. 브라우저 검증에서 native fetch 호출 컨텍스트 오류를 발견해 수정한 뒤 재검증했습니다.

## 범위 밖 또는 제한되는 사항

Tesseract 브라우저 OCR은 실제 엔진·한국어/영어 언어 파일로 테스트했습니다. OCR 응답은 대역으로 만들지 않습니다. 브라우저 테스트의 Firestore 저장 부분은 여전히 테스트 전용 REST 대역을 사용합니다. 테스트용으로 생성한 선명한 영수증 이미지와 빈 이미지를 검증했으며, 모든 업체의 실제 촬영 영수증 정확도를 보장하지 않습니다. 흐림·기울어짐·단위/숫자 오류에서는 원본 대조와 수정이 필요합니다. OpenAI 연결은 없습니다. 관리팀에 사진을 전송하거나 등록 후 다시 보여주지 않습니다.

공개 Firestore 규칙에서는 관리자 비밀번호가 실제 데이터 접근 권한을 보호할 수 없습니다. 웹앱 밖에서 직접 REST API를 호출하는 이용자를 차단하거나 입력 검증을 강제하지 못합니다. 실제 운영용 보안·개인정보 보호를 검증한 결과라고 해석하지 마세요.

실제 아이폰/갤럭시의 카메라 UI, HEIC 지원, Safari는 물리 기기에서 별도로 확인해야 합니다. Chromium 화면 크기 에뮬레이션 통과를 실제 Safari 통과로 표시하지 않습니다.
