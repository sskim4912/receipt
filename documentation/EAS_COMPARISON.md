# EAS 거래 비교창 — 2026-10-30

PC 연결의 거래 확인창을 세 열로 구성한다. 왼쪽은 EAS 전자전표, 가운데는
사용일자·금액·거래처의 일치/차이, 오른쪽은 원본 영수증 시스템 값이다.
기존 Aurora 파란색을 헤더·주요 버튼에 사용하고, 일치는 초록색, 표기 차이는
주황색과 텍스트로 함께 표시한다. 하단 확인·취소 버튼은 표와 별도로 고정한다.

목록에서는 날짜·금액 및 제공된 카드 끝 4자리가 정확히 같은 후보를 찾는다.
업체명은 후보 제외 조건으로 사용하지 않는다. 한 건이면 비교창에 바로 표시하고,
여러 건이면 아무 후보도 미리 선택하지 않는다. 사용자가 직접 후보를 선택한 뒤
비교해야 진행할 수 있다. 업체등록 Y가 아니면 진행 버튼을 비활성화한다.

‘네, 상세 확인’을 누른 경우에만 선택된 행을 다시 읽어 같은 거래인지 확인하고
날짜 셀을 더블클릭한다. 업체명 차이 승인은 그 행·영수증 ID·버전·원본 대조 값에
묶인 메모리 내 증명으로만 유지한다. 원본 영수증, 연결 payload와 DB는 변경하지 않는다.
상세에서 승인번호(앞자리 0 포함)·날짜·금액·제공된 카드 끝 4자리를 계속 대조한다.
전역 거래 검증 규칙을 완화하지 않고, 승인된 EAS 업체명만 해당 로컬 검증에 반영한다.
입력 전후 재대조와 3개 필드 값 유지 검증, 사용자 직접 저장은 그대로 유지한다.

‘아니오, 중단’, Escape 또는 창 닫기는 거래 열기·입력을 취소한다.
Enter만으로 표기 차이를 자동 승인하지 않는다. 회사 로그인 원본과 URL 등록은 변경하지 않는다.

속도 개선 코드에 있던 겹친 공지 대기 오류도 수정했다. 원본 공지 함수는 맨 위 공지
한 개만 닫으므로, 그 공지만 사라지는지 확인한 후 다음 공지를 처리한다.
닫기 실패·팝업 제한·알 수 없는 팝업 검사는 유지한다. 겹친 공지 2개 조건에서
기존 코드의 시간 초과를 재현하고 수정 후 통과를 확인했다.

## 검증

- Python 모의 DOM/입력/프로토콜/설치/성능 검사 65개 중 64개 통과, 1개 건너뜀.
  건너뛴 검사는 체크아웃 안의 비공개 로그인 원본 파일이 필요한 검사다.
  업로드된 원본 해시는 인계 문서와 별도로 일치 확인했다.
- 신규 비교 검사: 업체명 차이 승인, 원본 payload 불변, 상세 승인번호 불일치 중단,
  여러 후보의 선택 행 재검증, 취소 시 이동·입력 없음, 날짜·금액·카드 불일치 제외.
- 가상 디스플레이에서 실제 Tk 창을 렌더링하고 중앙 차이 표시를 시각적으로 확인했다.
  하단 버튼 표시, 확인, 창 닫기 취소, 다중 후보 미선택 차단·선택 진행,
  미등록 후보 진행 차단을 실제 위젯으로 확인했다.
- Linux 미리보기는 대체 한글 글꼴을 사용한다. Windows는 맑은 고딕을 우선한다.
- 실제 회사 SSO/EAS와 사용자 PC에서는 아직 재검증하지 않았다. 모의 검사는
  실전 성공이나 전체 구간의 3배 속도 개선을 증명하지 않는다.

## 적용

`aurora-eas-compare-update.zip`이 이전 속도 개선용 ZIP을 대체한다.
기존 연결 Edge를 닫고, 등록된 PC 설치 폴더의 `eas_receipt_bridge.py`를 별도 이름으로
백업한 뒤 ZIP의 같은 파일 한 개만 교체한다. 기존 백업을 덮어쓰지 않는다.
`eas_card_automation.py`, `eas_assistant.py`, `eas_protocol.py`, 로그인 및 등록은 그대로 둔다.
문제가 있으면 연결 Edge를 닫고 백업한 bridge 파일로 복구한다.

PC 파일 교체, main 반영, 운영 배포는 이 개발 검증에 포함되지 않는다.
