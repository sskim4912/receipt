# 배포·운영 범위

## GitHub Pages

저장소 `sskim4912/receipt`의 `main` 브랜치 `/docs`를 Pages 배포 원본으로 사용합니다. 빌드 결과에 `.nojekyll`이 포함되며 앱 경로는 `/receipt/`입니다.

사용 주소: **https://sskim4912.github.io/receipt/**

소스 수정 후:

```bash
npm ci --cache /workspace/.npm-cache
npm test
npm run build
npm run test:e2e
# 확인한 소스와 docs 빌드 결과를 함께 main에 반영
```

Node.js·npm은 개발/빌드 시에만 필요합니다. 사용하는 PC·휴대폰에는 별도 프로그램을 설치하지 않습니다. 브라우저의 일반 HTTPS 사진 선택/카메라 UI를 사용합니다. 모바일 기기에 따라 카메라 선택창과 지원되는 이미지 형식은 달라질 수 있습니다.

## Firebase Spark

사용자가 제공한 `receipt-71a9c` 웹 설정을 소스에 넣었습니다. Firestore만 연결합니다. Firebase Storage를 생성하거나 호출하지 않으며 Cloud Functions·Authentication·OpenAI도 호출하지 않습니다. 결제 설정·요금제·Firestore 보안 규칙을 변경하지 않았습니다.

현재 공개 규칙 `allow read, write: if true`를 전제로 합니다. 비밀번호는 클라이언트에서 PBKDF2로 확인하는 화면 잠금일 뿐입니다. 프로젝트의 모든 자료가 익명 API 호출에 노출되는 제약을 화면과 README에 표시했습니다. 실제 개인정보를 취급하는 운영용 보안 구성으로 보지 마세요.

관리자 비밀번호는 첫 관리자 접속 시 사용자가 직접 설정합니다. 소스에 기본 비밀번호를 넣지 않았으며 검증 과정에서도 실제 프로젝트의 `appSettings/adminGate`를 생성하지 않았습니다. 비밀번호를 잊으면 프로젝트 소유자가 해당 화면 잠금 설정의 초기화 여부를 판단해야 합니다. 자동 초기화·삭제 버튼은 제공하지 않습니다.

## 네트워크·복원

클라우드 개발에서는 `firestore.googleapis.com`, GitHub API·Pages, npm 레지스트리에 접근해야 합니다. 선택적인 WebKit 테스트 브라우저 다운로드는 Playwright 배포 도메인에 접근합니다. GitHub Pages에서 앱을 사용하는 사용자는 Firestore HTTPS 접근이 필요합니다.

재사용 환경 설정의 설치 스크립트와 시작 안내를 정적 앱 기준으로 교체했습니다. 이전 서버 버전의 OpenAI 키·Firebase 서버 인증 요구사항은 이번 앱에 필요하지 않습니다. 기존 환경 설정에 남아 있는 요구사항은 환경 설정에서 제거해도 됩니다. **OpenAI 키를 새로 요청하거나 사용하는 작업을 하지 않습니다.**

현재 브라우저에만 사진과 입력 중인 값이 있습니다. 페이지를 새로고침하거나 닫으면 미등록 입력과 사진은 사라집니다. 등록된 내역은 Firestore에 남고 이름/등록번호로 다시 조회할 수 있습니다. 브라우저 저장소에 사진을 지속 저장하지 않습니다.

## 향후 OpenAI 자동 인식

1. 브라우저 코드에 API 키를 넣지 않는 별도 안전한 서버/API를 선택합니다. 현재 단계에서 서비스를 생성하거나 유료 요금제로 전환하지 않습니다.
2. 서버에서 키를 보호하고 요청 인증·호출 한도·인식 비용 제한을 적용합니다. 현재 공개 Firestore 규칙과 화면 잠금도 실사용 가능한 인증/권한 구조로 교체해야 합니다.
3. 사용자의 임시 사진을 분석 요청으로 전달하는 개인정보 처리 범위를 합의합니다. 저장하지 않는다면 분석 후 파일을 폐기하고 결과만 반환합니다.
4. 핵심 날짜·금액·업체명·승인번호를 엄격하게 검증하고 불확실한 항목을 확인불가로 반환합니다. 사용자 확인 이후에만 저장합니다.
5. 현재 브라우저 OCR의 실패·재시도·3회 후 수기 전환 흐름에 OpenAI 인식 결과를 연결합니다. 로컬 OCR과 외부 API 사용을 명확히 구분합니다.
6. 실제 정상/흐림/빛반사/부분 잘림/승인번호 없는 영수증으로 검증합니다. 숫자 정확도를 보장한다고 주장하지 않습니다.

기존의 원본 사진 보관·관리자 썸네일 조회 기능을 다시 원한다면, 현재의 ‘사진 저장 금지’ 원칙 변경과 저장소·요금제 선택은 별도로 승인받아야 합니다.

## 브라우저 OCR 배포

`npm run build`는 먼저 `scripts/prepare-ocr.mjs`로 lockfile에 고정된 Tesseract Worker, LSTM WebAssembly 코어 3종, 한국어·영어 언어 파일과 라이선스를 `public/ocr/`에 준비합니다. Vite는 이를 배포용 `docs/ocr/`로 복사합니다. `public/ocr/`는 재생성하므로 Git에서 제외하고 **완성된 `docs/` 전체는 main에 포함**합니다. 런타임 CDN·외부 OCR 서버·API 키가 필요하지 않습니다. Worker가 읽는 사진·처리한 픽셀·전체 OCR 텍스트는 임시 메모리에만 존재하며, Firestore에는 사용자가 확인한 입력정보와 인식 엔진/실패 횟수만 저장합니다.

첫 사용 약 8~9MB 다운로드 후 브라우저 HTTP 캐시를 이용할 수 있습니다. OCR 라이브러리의 IndexedDB 캐시는 비활성화했습니다. 120초 제한·취소·엔진 다운로드 오류에서 Worker를 종료하고 직접 입력을 제공합니다. 배포가 끝나면 새로고침 후 촬영 버튼 → 인식 진행 → 원본 대조 → 추가정보 → 등록을 확인하세요.
