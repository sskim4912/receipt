# EAS 전자전표 연결 — 기존 접속 코드 보존 버전

관리자 상세의 영수증 **한 건**을 PC에 설치된 Windows 프로그램으로 직접 전달합니다.
최초 한 번 Windows 사용자별로 등록하며, 다음 날·재부팅·브라우저 재접속 때 다시 다운로드하지 않습니다.
연결 프로그램은 특정 직원 이름이나 PC 경로를 사용하지 않습니다. 모든 관리자가 같은 설치 파일과 버튼을 사용합니다.
기존 영수증·중복 예약·사진·처리상태·전표 O/X를 쓰거나 변경하지 않습니다.
비용구분·계정과목·저장·업체등록·오사용·기술개발지원·현장멘토·비용배부는 조작하지 않습니다.
실제 Windows 앱 실행·회사 EAS 입력은 사용자 PC에서 검증해야 합니다. 클라우드 검사는 모의 거래로 수행하며 전표 저장은 하지 않습니다.

## 파일 선택 없는 PC 직접 연결

1. 관리자 상세 → 전자전표 연결 → **최초 1회 PC 설정 · 연결 도움말**을 펼칩니다.
2. 공통 설치 ZIP을 받아 전체 압축 해제 후 `INSTALL.cmd`를 실행합니다.
3. 설치 프로그램이 PyCharm 프로젝트, 기존 검증 폴더, 기존 설치 폴더에서 검증된 `eas_card_automation.py`를 자동 탐색합니다.
   승인된 SHA-256과 일치한 원본만 사용하며 공개 저장소/설치 ZIP에 원본은 넣지 않습니다. 찾지 못한 경우에만 한 번 선택합니다.
4. 정상 작동한 기존 Python/Selenium 환경을 자동 선택하고 PC 연결을 등록합니다.
   없으면 설치 폴더에 전용 가상환경을 만들고 Selenium 4.27.1을 설치합니다. 기존 프로젝트나 시스템 패키지는 변경하지 않습니다.
   설치 프로그램 자체를 실행할 Python/tkinter는 PC에 필요합니다. 회사 정책으로 패키지 다운로드가 차단되면 명확한 오류로 중단합니다.
5. 이후에는 **EAS 보조 프로그램으로 연결**만 누릅니다. 브라우저의 외부 프로그램 열기를 허용합니다.
6. PC에서 전달된 영수증을 확인하고 승인하면 기존 Edge 접속 흐름이 시작됩니다.

웹 연결은 사용자가 누르는 네이티브 앱 링크를 별도 대상으로 엽니다. 숨겨진 iframe은 사용하지 않습니다.
관리자 페이지는 유지하며, 브라우저의 앱 열기 확인은 사용자가 허용해야 합니다.
화면의 **PC 연결 상태 확인**은 `aurora-eas://check`만 전달하여 설치를 진단합니다.
영수증/로그인 정보나 EAS 접속 없이 정상 등록 안내가 뜨는지 확인할 수 있습니다.
Windows/브라우저가 붙이는 빈 경로의 끝 `/`와 스킴·호스트의 대소문자 차이를 허용합니다.
실제 영수증 Base64URL 경로의 대소문자는 그대로 보존하고 알 수 없는 경로·쿼리·fragment는 거부합니다.
‘앱을 찾을 수 없음’이면 최초 등록이 필요하고, 브라우저가 차단하면 회사 정책과 외부 앱 열기 허용 여부를 확인합니다.

설치 위치는 `%LOCALAPPDATA%/AuroraEAS/v1-임의번호`이고 사용자 레지스트리의
`HKCU/Software/Classes/aurora-eas`에 고정 Python 실행 파일과 수신기 경로를 등록합니다.
연결 등록에는 로그인 정보·영수증 데이터를 넣지 않으며 시작프로그램·서비스·로컬 HTTP 서버를 등록하지 않습니다.
같은 Windows 사용자에서는 등록이 유지됩니다. 다른 PC/Windows 계정은 최초 설정이 한 번 필요합니다.
IT 정책이 등록을 막으면 담당자 확인이 필요하며 브라우저 정책을 우회하지 않습니다.
기존 설치 폴더의 `UNINSTALL.cmd`로 등록을 해제할 수 있고 파일은 보관합니다.

`aurora-eas://connect/BASE64URL`로 UTF-8 허용 필드만 전달하며 서버/Firestore를 거치지 않습니다.
Base64는 암호화가 아닙니다. URL과 PC 프로세스 인수에 이름/목적이 포함되므로 공유하지 마세요.
인증정보·사진·전체 카드번호·전체 DB 문서는 전달하지 않습니다.
수신기는 주소 형식·길이·엄격한 기존 스키마·요청 후 5분 이내 여부를 검사합니다.
운영체제 URL만으로 발신 사이트를 인증할 수 없으므로 Edge 실행 전 PC에서 영수증 내용을 확인합니다.
기존 거래 대조와 입력 전 확인도 유지합니다. 쉘 명령, 외부 URL 다운로드, 저장 명령은 받지 않습니다.
동시 실행은 Windows 세션 mutex로 차단합니다. 이전 연결의 Edge를 닫으면 다른 영수증을 연결할 수 있습니다.
웹은 PC의 실행 성공을 확정할 수 없으므로 ‘실행 완료’ 대신 프로그램 열기/설치 안내를 표시합니다.

설치 ZIP은 `python3 tools/eas/build_windows_package.py`로 재생성하고 Vite가 `docs/downloads/`에 복사합니다.
Windows 명령 파일은 패키징 시 CRLF 줄바꿈으로 강제하며 진입 명령 파일은 ASCII로 검사합니다.
이전 설치 ZIP의 LF 줄바꿈/코드 페이지에 따른 cmd.exe 해석 오류를 피하도록 수정했습니다.
기존 Cloudflare Workers 정적 파일 배포 구조를 유지합니다. Python 실행은 Windows에서만 수행합니다.

## 기존 정상 코드 보존

`tools/eas/eas_card_automation.py`는 사용자가 정상 작동을 확인하여 제공한 코드 원문입니다.
바이트 단위로 그대로 복사했으며 SHA-256은 다음과 같습니다.

```text
d66a47a6c4ea3094cc3dc2ec8c39bd57601cda3b24eac2ef89acc6e3001e3186
```

신규 `eas_receipt_bridge.py`가 원본의 다음 함수를 같은 driver로 호출합니다.

```text
start_edge → open_sso_login → wait_for_login → 2초 대기
→ open_eas_card_list → close_all_startup_notices → show_final_status
→ 신규 거래 대조·3개 항목 입력 → keep_browser_open
```

로그인 방식·로그인 자동 감지·EAS 이동·공지 닫기 함수 자체를 변경하지 않았습니다.
로그인 후 PyCharm Enter 입력을 추가하지 않았으며 신규 확인은 Windows 확인 창으로 받습니다.
원본 `main()`은 마지막 화면 유지 루프에서 대기하므로 직접 호출하지 않고 기존 함수를 순서대로 호출합니다.
원본이 출력하는 전체 URL·예외에 인증 쿼리가 포함될 가능성이 있어, 연결 프로그램은 원본 함수의
콘솔 출력만 버리고 별도의 단계 안내를 표시합니다. 이 과정에서 로그 내용을 저장하지 않습니다.
원본을 단독 실행할 때의 출력은 그대로이므로 해당 콘솔 전체를 공유하지 마세요.

## 파일 구성

| 파일                                                   | 역할                                                            |
| ------------------------------------------------------ | --------------------------------------------------------------- |
| `eas_card_automation.py`                               | 사용자 정상 접속 기준 원본. 수정하지 않음                       |
| `eas_receipt_bridge.py`                                | 새 실행 파일. 기존 함수 재사용·거래 대조·확인 창·입력 연결      |
| `eas_assistant.py`                                     | JSON 검증·거래 비교·3개 입력의 공통 함수. 기본 실행은 로컬 검사 |
| `requirements.txt`                                     | 실행용 Selenium 의존성                                          |
| `requirements-dev.txt`, `test_*.py`, `tests/fixtures/` | 모의 화면과 실패 상황의 개발 검증                               |

Python 파일은 부분 코드가 아닌 전체 파일입니다. 위 실행용 Python 3개를 같은 폴더에 둬야 합니다.
이전의 빈 `selectors.example.json`을 채울 필요는 없습니다. 현재 연결 실행은 확인된 화면 구조를 사용합니다.
기존 `eas_assistant.py --edge`도 새 연결 코드로 위임하지만, 아래의 새 실행 파일 사용을 권장합니다.
이전 `--selectors`·`--driver` 옵션은 정상 기준 코드와 실행 방식이 달라질 수 있어 사용하지 않습니다.

## Windows / PyCharm 설치·실행

Python 3.10 이상과 Microsoft Edge가 필요합니다. ZIP은 압축을 해제하고 사용하세요.
이미 정상 작동한 PyCharm 환경이 있다면 **그 interpreter를 그대로 사용**하고 압축을 푼 폴더의
`eas_receipt_bridge.py`를 실행하는 것이 우선입니다. 기존 프로젝트의 원본 파일을 덮어쓰거나
정상 환경의 Selenium 버전을 바꾸지 마세요. 아래 가상환경 설치는 새 환경이 필요할 때만 사용합니다.
독립 실행 패키지에서 PowerShell로 압축을 푼 폴더를 열고 다음을 실행합니다.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe eas_receipt_bridge.py
```

저장소 내부에서 실행한다면 다음 명령을 사용합니다.

```powershell
py -m venv .local\eas-venv
.\.local\eas-venv\Scripts\python.exe -m pip install -r tools\eas\requirements.txt
.\.local\eas-venv\Scripts\python.exe tools\eas\eas_receipt_bridge.py
```

PyCharm에서는 해당 가상환경을 interpreter로 설정하고 `eas_receipt_bridge.py`를 실행합니다.
개인 Edge 프로필·쿠키를 복사하지 않습니다. EdgeDriver 준비 방식은 원본 그대로이며 연결 실행 시 전용 고정 프로필을 지정합니다.
드라이버 다운로드·회사 정책으로 실패하면 보안 설정이나 TLS 검증을 끄지 말고 담당자에게 확인하세요.

## 기존 파일 방식 (설치 제한 시 대체)

1. 영수증 웹 관리자에서 대상 한 건을 펼치고 **전자전표 연결 → EAS 연결 파일 다운로드**를 선택합니다.
2. 연결 프로그램을 실행하고 받은 `eas-등록번호.json`을 선택합니다.
3. 원본 코드가 연 Edge에서 직접 로그인합니다. 로그인 후에는 자동으로 EAS 목록까지 이동합니다.
4. 현재 로드된 목록의 날짜·금액과, 원본에 값이 있는 카드 끝 4자리·거래처를 대조합니다.
5. 후보가 정확히 한 건이고 업체등록 Y일 때 Windows **EAS 거래 확인** 창을 띄웁니다.
6. 사용자가 예를 누르면 같은 행을 다시 대조하고 해당 행의 **날짜 셀만 더블클릭**합니다.
7. 상세의 승인번호·사용일자·사용금액을 원본과 대조하고 카드 끝 4자리도 목록에서 확인한 값과 비교합니다.
   주소 변경만으로 로딩 완료로 판단하지 않고, 거래 정보와 3개 입력란이 표시되고 수정 가능해질 때까지 최대 20초 기다립니다.
8. **실사용자·인원수·목적 입력 확인** 창에서 데이터 최신 여부·비용구분·계정과목을 직접 확인합니다.
9. 예를 누르면 3개 입력란만 채우고 포커스 이동 후에도 값이 유지되는지 확인합니다.
10. 화면을 유지합니다. 전체 거래와 React 검증 표시를 다시 확인한 후 사용자가 직접 저장합니다.

입력 대상은 `input[name="useName"]`, `input[name="empCnt"]`, `input[name="resn"]`로 고정됩니다.
프로그램은 저장·결재·승인·확인·전송 버튼을 누르거나 Enter 제출을 하지 않습니다.
프로그램 종료는 Edge 닫기 또는 PyCharm 정지 버튼입니다. 별도 콘솔 Enter는 필요하지 않습니다.

운영 반영 여부는 Cloudflare 배포 결과와 실제 화면에서 확인해야 합니다.
로컬 검사 통과나 이 문서는 실제 PC 입력·전표 저장 완료를 뜻하지 않습니다.

## 확인된 DOM과 보수적인 제한

- 사용내역 grid는 제공된 화면의 `sheetEpCcVouc0001_1`로 한정합니다. 취소 목록은 탐색하지 않습니다.
- 행은 `tr.IBDataRow`, 열은 `HideCol숫자useDate/cardNum/useAmt/joinStorName/regiYn`을 읽습니다.
- `AR9`, 행 순서, `IBSheet[6]`, 숫자 `6`을 고정하지 않습니다. 같은 행의 열·등록 상태를 함께 확인합니다.
- 상세는 `승인번호`, `사용일자`, `사용금액`, `카드번호` 항목명이 있는 `th/td` 행을 읽습니다.
- 생성되는 MUI CSS 해시나 실제 거래 숫자를 selector에 고정하지 않습니다.
- 상세 사용일시는 확인된 `YYYY.MM.DD HH:mm:ss` 형식을 검사하고 날짜만 비교합니다.
- 업체등록 Y는 **직접 열기로 승인한 같은 목록 행**에서 확인한 일시적 증거입니다. 상세에 등록값을 만들어 넣지 않습니다.
- 이 증거는 같은 연결 파일·등록번호·버전에 묶고 10분 이내에만 사용합니다. 거래가 바뀌면 중단합니다.
- 데이터의 승인번호가 없거나, 같은 조건의 후보가 여러 개면 자동 선택하지 않습니다.
- 현재 로드·렌더링된 행만 검사합니다. 전체 페이지·스크롤 밖·서버의 모든 후보를 검색했다고 주장하지 않습니다.
  후보가 없거나 여러 개라면 EAS의 기존 검색 기능으로 범위를 좁힌 뒤 새로 실행하세요.
- 사업자번호는 연결 파일에 있을 수 있지만, EAS 거래처 옆 숫자가 사업자번호라는 DOM 근거는 아직 없어
  해당 숫자를 사업자번호로 추정하거나 현재 비교에 사용하지 않습니다.
- 확인된 상세 주소는 `/ep/cc/vouc/EpCcVouc0002`입니다. iframe·모달 구조로 바뀌면 추측하지 않고 중단합니다.

## 실패·개인정보·저장 정책

후보 없음·복수 후보·업체 미등록·불명확한 등록 상태·거래 불일치·로그인 만료·알림·남은 팝업·화면 구조
변경·입력 불가·입력 길이 초과·입력값 복귀·사용자 취소 시 중단합니다. 다음 거래로 자동 진행하지 않습니다.
실패 메시지가 먼저 표시되고 화면은 유지됩니다. 일부 입력 후 실패했을 수 있으니 사용자가 확인해야 합니다.
PC 연결 실행에서는 중단 단계와 안전한 원인을 별도 Windows 안내 창으로 표시한 뒤 기존 화면 유지 루프로 들어갑니다.
화면 로딩 중 생기는 요소 교체는 입력 없이 기다리되, 거래 불일치·복수 입력란·팝업·세션 변경 검증은 우회하지 않습니다.
입력란 `.value` 일치는 React 상태나 서버 저장 성공을 보장하지 않습니다. 실제 EAS에서 별도 검증이 필요합니다.

ID·Password·PIN·OTP·쿠키·인증토큰을 읽어 보관하거나 자동입력하지 않습니다.
JSON에는 사용자 이름과 사용목적 등 업무 정보가 포함되므로 업무용 PC에서 사용하고 Git·공유 폴더에 넣지 마세요.
24시간이 지난 연결 파일은 거부합니다. 원본을 수정했다면 반드시 다시 내려받으세요.
서버의 최신 문서 버전을 재조회하지는 않으므로 입력 직전에 원본과 EAS를 직접 확인해야 합니다.
기존 Firestore status나 전표 O/X는 자동 변경하지 않습니다.

실제 Windows Edge·회사 SSO·EAS 입력과 React 상태 검증은 사용자 PC에서 남아 있습니다.


## 로그인 상태 유지

새 연결 프로그램은 `%LOCALAPPDATA%/AuroraEAS/EdgeProfile`을 EAS 전용 Edge 프로필로 사용합니다.
첫 실행에서 직접 로그인하면 Edge가 유지하는 쿠키·사이트 저장소를 다음 실행에서도 재사용합니다.
설치 버전 폴더 바깥에 두므로 재설치·재부팅 후에도 같은 Windows 사용자는 같은 프로필을 사용합니다.
기존 임시 Selenium 창이나 평소 사용하는 Edge의 로그인 상태는 가져오지 않으므로 새 버전 최초 실행에는 로그인이 필요합니다.
기존 SSO 접속과 로그인 완료 감지 절차를 유지하며, 유효한 세션이 있으면 SSO의 기존 자동 로그인 동작을 이용합니다.
회사 정책에 따른 세션 만료·로그아웃·OTP·추가 인증 시에는 직접 인증해야 합니다.
프로그램이 비밀번호를 저장하거나 쿠키를 별도 파일로 내보내지는 않지만, 전용 프로필 자체에는 Edge가 관리하는 인증 상태가 남습니다.
이 폴더는 공유하거나 Git에 올리지 마세요. 공용 Windows 계정에서는 다른 사용자도 같은 세션을 사용할 수 있습니다.
이전 EAS Edge 창을 모두 닫은 후 다음 연결을 실행하세요. 프로필이 사용 중이면 임시 프로필로 대체하거나 초기화하지 않습니다.
로그인 기억을 초기화하려면 전용 Edge에서 로그아웃하거나 모든 EAS Edge 창을 닫고 위 `EdgeProfile` 폴더를 삭제하세요.
기존 설치 사용자는 새 ZIP으로 `INSTALL.cmd`를 다시 실행해야 변경 사항이 적용됩니다.


## 첫 사용자 설치와 바탕화면 바로가기

연결 창 맨 위의 **처음 사용 · PC 자동 설치 다운로드**에서 `AuroraEAS-Setup.cmd`를 받습니다.
사용자가 이 파일을 실행하면 운영 포탈의 ZIP을 다운로드하고 SHA-256을 확인한 다음,
Windows의 실제 바탕화면(OneDrive 이동 포함)에 새 폴더로 풀고 `INSTALL.cmd`를 실행합니다.
프로그램은 사용자별 LocalAppData에 설치하고 바탕화면에는 업무 포탈과 PC 연결 확인 바로가기를 만듭니다.
브라우저만으로 파일 실행·무승인 설치는 할 수 없습니다. 회사 정책이 CMD를 차단하면 ZIP 직접 다운로드를 사용하세요.
ZIP 다운로드와 PC 연결 상태 확인은 ‘설치·연결이 안 될 때’ 도움말 안에 표시합니다. 창의 제목·설치·연결 버튼은 고정하고 내용만 스크롤합니다.
Python/tkinter와 검증된 사내 `eas_card_automation.py`는 여전히 필요합니다.
해당 코드가 없는 첫 사용자는 사내 담당자에게 받아 선택해야 하며 공개 ZIP에 사내 접속 코드를 넣지 않습니다.
`앱을 찾을 수 없음`이면 먼저 설치를 완료하고 PC 연결 상태 확인으로 등록을 확인하세요.
정상 등록 확인은 SSO·실제 거래 접속 성공을 대신하지 않습니다.
이전 버전 자동 설치 CMD는 새 ZIP과 해시가 다르면 중단하므로 포탈에서 최신 CMD를 다시 받으세요.


연결 창은 사용일자·업체명·금액을 확인한 뒤 EAS 연결을 누르는 순서입니다.
처음 사용하는 PC의 설치 다운로드는 연결 버튼 아래에 표시합니다.
‘처음 한 번, 간편하게 시작하기’는 파일 다운로드 → AuroraEAS-Setup.cmd 직접 실행 → 이후 연결의 3단계입니다.
CMD를 실행하면 ZIP 다운로드·압축 해제·설치 시작이 자동 진행되지만, 다운로드만으로 실행되지는 않습니다.
직원용 독립 EXE는 아직 제공하지 않으며 Python·사내 기준 코드가 필요한 기존 설치 요건은 도움말에서 안내합니다.
